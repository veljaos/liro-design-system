# @veljaos/tokens

## 1.0.0

### Major Changes

- e976399: 1.0.0, the first stable release of the Liro Design System.

  - **What it is:** the tokens, components and page templates of 0.1.0-alpha.5, with the screens around liro-folio's documents added below; nothing else in the API changed. This release makes it stable. From now on a breaking change raises the major version, and releases are published under the `latest` dist-tag.
  - **Upgrading from an alpha:** follow the release notes of 0.1.0-alpha.5 below (removed templates and print parts, read only instead of `disabled`, `unavailableReason`, renamed props), then the earlier alpha entries if you come from further back.
  - **One import to add for Chinese or Japanese.** The Chinese and Japanese font faces (330 `@font-face` rules, about 96 KB of CSS gzip) moved out of `@veljaos/tokens/tokens.css` into `@veljaos/tokens/fonts-cjk.css`. An application that shows Chinese or Japanese text adds `import '@veljaos/tokens/fonts-cjk.css'` after `tokens.css`; every other application changes nothing and loads about 96 KB less render-blocking CSS on every page (the example list and document pages: 151.6 → 32.0 KB gzip). `@veljaos/ui/styles.css` stays one file: all subpaths together add 4 KB to it.
  - **New: the screens around liro-folio's documents.** They draw what the application passes in and report through callbacks; none calls liro-folio or any other service (a test checks `@veljaos/ui` for imports of liro-folio, Liro Bridge or liro-core and for network calls).
    - `PageViewer` shows liro-folio's page images in each page's own size from the metadata (A4 portrait and landscape, A5, thermal rolls), with "Fit width", "Fit page" (`defaultFit="page"` to open so), `onDownload` ("Download PDF") and `areas`: the signature, text and choice areas drawn over the pages and listed for screen readers.
    - `SignaturePlacer` places one signature box per signer (labelled with the name, 190 × 48 pt by default) by a press or tap, a drag, the arrow keys, or on one of the document's empty signature fields. A box stays on its page and never covers another area. It returns `{ page, x, y, width, height }` in PDF points from the page's bottom-left corner. Helpers: `toPdf`, `toTopLeft`, `boxAtPoint`, `nudgeBox`, `keepOnPage`, `placementFits`, `pdfBoxesOverlap`, `firstFreeSpot`, `fitPageZoom`, `PAGE_SIZES`, `SIGNATURE_SIZE`.
    - `DocumentOptionsDialog` ("Print or export"): the document type and the actions first; languages (one, or two for a bilingual document), status marks, QR code, signature mode and paper under "More options", every choice from the application; "Remember these options for …" when the application keeps them; the application's preview beside them. A full-screen sheet on phones.
  - **What else changed since 0.1.0-alpha.5** (no change to the published code's behaviour):
    - every component with text keeps an Arabic and a Japanese story, checked in CI, and Serbian Latin and Cyrillic were checked across the catalogue;
    - a performance budget: the list and document example screens stay under 250 KB of JavaScript and 35 KB of CSS (gzip);
    - comments in the code say what it does, without history;
    - the documentation is short rule documents by subject in `docs/`, a README and a slim AGENTS.md.
