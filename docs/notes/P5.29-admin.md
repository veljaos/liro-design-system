## 1. Decision entries (for `docs/decisions.md`)

- **2026-10-14 — HealthList: one component for monitored things (P5.29 a, b).** The library had
  nothing for "is it working, and since when?": StatusTimeline is one process's states in order,
  SetupChecklist steps done once, SessionList devices, KeyValueList values without a state, and
  JobProgress one job. HealthList (`components/health-list.tsx`, logic in `health-logic.ts`) shows
  connections, services, queues, databases, backups, regions — anything monitored — as rows: the
  name with its detail and the application's note; the state as a StatusBadge with the
  application's words and tone and an icon from its `kind` (`up` CircleCheck, `degraded`
  CircleAlert, `down` CircleX, `maintenance` Wrench, `unknown` CircleHelp; the application may
  give another icon) — never colour alone; the figures as label over value (`metrics`, the
  application's text); the last success ("Never" when null) and the last error with its time and
  message (`healthFacts`); and the application's actions (Retry, "Open log") as neutral secondary
  small buttons named with the thing ("Retry: SEF (e-invoicing)"), busy while a returned promise
  runs. It judges nothing: a figure never becomes a state, nothing is counted. Desktop: one card
  whose rows share one grid (CSS subgrid), so the columns line up across rows; an optional title
  row with `headerActions`. Phones: one card per thing (owner), the title above the cards (never
  cards in a card); figures and times as label / value rows, the error's message in full, the
  actions at the bottom. Loading: skeleton rows; nothing: the application's words (`emptyText`,
  default `messages['health.empty']`); a failed load: a danger Alert. Decided by me: the state's
  kind drives only the icon, the tone stays the application's (its status-to-tone map), as for
  every StatusBadge.
- **2026-10-14 — The administration of a tenant (P5.29 a).** Built from the library only:
  - **Overview** is a DashboardPage: users, active sessions, failed sign-ins today, accounts
    without two-factor sign-in as StatCards; failed and blocked sign-ins of the last seven days
    as a stacked BarChart in the tones of the two states (warning, danger); the licences as a
    SectionCard with "24 of 30 seats used", a ProgressBar and a KeyValueList; the integrations
    with errors as a HealthList; the accounts without two-factor sign-in as a DataTable.
  - **Sign-in activity** is a ListPage: saved views (All, Failed and blocked, Today), a FilterBar
    (user, result, period — all inline), Export; a DataTable with when, user (name and e-mail),
    result (Success / Failed / Blocked in the application's words and tone), reason, device and
    browser, the approximate place, and the IP address as a MaskedValue: masked by default,
    shown after a reason from the application's list (or "Other"), the access logged; Hide.
  - **Audit log** is a ListPage: views (All, Access and settings, Documents and customers),
    FilterBar (changed by, record, period, search), Export; a DataTable of when, who, record
    (with its kind), field and the change — the old value struck through (`del`), an arrow
    (mirrored in right-to-left), the new value (`ins`, no underline), "From" / "to" for assistive
    technology, "empty" for nothing. **Never edited or deleted:** no selection, no row actions; a
    row opens the whole entry read only in an end Drawer (before, after, address, request id);
    the table's note says the log cannot be changed (`rowLimitMessage`).
  - **Security** is a page of SectionCards: two-factor sign-in per user (a DataTable; "Reset
    two-factor sign-in" confirmed, "Send a reminder"); signed-in devices of the user chosen in a
    SelectField with SessionList's Sign out and "Sign out everywhere" (confirmed; SessionList's
    own "Sign out all other devices" is for the person's own account, so it is not used for
    another user); API keys and tokens (name with the key's visible start, access, created by,
    last used, expires, state; Revoke from the row's menu with a destructive ConfirmDialog titled
    by the action with the key as its subject, D22; a revoked key stays listed as Revoked); the
    password and session policy as a KeyValueList from the Core's data with "Change policy".
  - **Integrations** is a HealthList of every connection (SEF, two banks, e-mail, Liro Bridge,
    the tax administration, the exchange rates) with Retry where the application offers it.
- **2026-10-14 — The platform's system status and network (P5.29 b, two views).** **System
  status** is a DashboardPage across every tenant: services up, 30-day uptime, response time
  (p95) and error rate as StatCards; response time (p95 and median) and the error rate for the
  last 24 hours as LineCharts; services, queues, databases and storage, and backups (the last
  good backup, the copy to the second region, the weekly restore test) as HealthLists;
  certificates (expiry and renewal) and scheduled maintenance as DataTables. **Network and
  infrastructure**: regions as a HealthList (latency, nodes, open alerts), the latency between
  regions as a LineChart, open alerts as a DataTable (Acknowledge in the row menu), nodes as a
  DataTable with a FilterBar (region, role, health; address, CPU, memory, latency, alerts).
- **2026-10-14 — Example data for administration (P5.29).** Invented throughout; IP addresses
  only from the documentation ranges (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24,
  2001:db8::/32), e-mail addresses and host names at example.com, certificate issuers
  "Illustrative CA". Today 14.10.2026, now 09:40 (the screens' `Tenant today`).
