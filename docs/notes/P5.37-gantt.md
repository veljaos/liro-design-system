## 1. Decisions (for `docs/decisions.md`)

- **2026-10-14 — Gantt on SVAR React Gantt 2.7.3, MIT edition, `@veljaos/ui/gantt` (P5.37, owner: "an MIT library: evaluate SVAR React Gantt (MIT edition, never PRO) and Frappe Gantt …; pick one, pin it, add its notice, record why").** SVAR was chosen over Frappe Gantt (evaluation of 2026-10-14): React-native and typed, milestones, a hierarchy (summary rows with `parent`), all four dependency types, progress, an action bus to stop and report edits (`api.intercept`), React templates for bars (`taskTemplate`), scale labels as functions (`format`), `readonly`, and colours behind CSS variables. Frappe has no keyboard, no ARIA, no milestones or hierarchy, no React integration, takes "today" from the device's clock (D25) and writes task names with `innerHTML`. **Pinned at 2.7.3** (published 2026-09-09, more than two weeks old); 2.8.x was too new. Checked in 2.7.3's code before pinning: `type: 'milestone'`, `type: 'summary'` with `parent` and `open`, links `e2s` / `s2s` / `e2e` / `s2e`, `progress` with its drag marker, `api.intercept`, `taskTemplate`, `scales[].format` as a function, `readonly`, `start` / `end` with `autoScale={false}`. The MIT store switches the PRO features off at runtime (`markers`, baselines, critical path, undo, auto-scheduling, calendars, resources); none is used.
  1. **A subpath of its own** (tsup entry `gantt`, `exports["./gantt"]`), as `@veljaos/ui/diagram`: only `dist/gantt.js` imports `@svar-ui/react-gantt`; the root `@veljaos/ui` exports nothing of it. `packages/ui/src/gantt/`: `gantt.tsx` (the component, the table, the chart wrapper), `gantt-parts.tsx` (the row words, the list by phase, the four dialogs), `gantt-logic.ts` (pure, tested: `ganttRows`, `phaseGroups`, `chartDate`/`chartEnd`/`dayOfChartDate`, `durationDays`, `movedDates`, `draggedDates`, `dragChange`, `chartRange`, `nowPosition`, `isProgress`, `progressWidth`, `linkType`/`dependencyType`, `predecessors`, `dependsOn`, `dependencyCandidates`, `applyGanttChange`, `nextDependencyId`, `forbiddenGanttPackages`), `gantt.css`. The consumer-check app renders an editing Gantt from the packed subpath (`apps/consumer-check/src/GanttExample.tsx`).
  2. **Never the trial, PRO or GPL builds.** `@svar-ui/trial-*` (a paid licence) and `wx-react-gantt` (GPLv3, SVAR's old name) must never enter the lockfile: `gantt-logic.test.ts` reads `pnpm-lock.yaml` and fails if `forbiddenGanttPackages` finds either.
  3. **SVAR's style sheets, themes and icon font are not shipped.** SVAR's `style.css` / `all.css` hold raw colours in their theme blocks; the theme components (`Willow`, `WillowDark`, `Material`) load `https://cdn.svar.dev/fonts/wxi/wx-icons.css` when rendered. Gantt renders none of them. `gantt/gantt.css` sets the `--wx-*` variables SVAR's components read to Liro tokens in the `.liro-gantt` scope only and keeps the structural rules of `@svar-ui/react-gantt`'s `dist/index.css` (MIT, noted in THIRD-PARTY-NOTICES.md) that position and layer the chart's parts, selected by SVAR's stable class names (`wx-bar`, `wx-scale`…), never its hashed ones; imported into the base layer of `styles.css` (no hex, rgb or hsl). SVAR's CellGrid paints the grid into a canvas image from a colour it reads once; the image is hidden and the grid is two CSS gradients in `border.subtle`, so it follows the theme. SVAR's one icon on the chart (the X that removes a chosen dependency, `wxi-close`) is lucide's `x` as a CSS mask in the button's colour. SVAR measures and positions in physical pixels (`left`, `dir="ltr"` on the chart), so `left`/`right` in `gantt.css` are the time axis, not page layout.
  4. **Controlled; every edit reported, nothing saved.** Gantt passes its rows to SVAR and intercepts what would change them: a drag (`update-task` with a whole number of days; `drag-task` is allowed while it moves, blocked on a phase), a progress drag, a dependency drawn between two bars' end dots (`add-link`), a chosen dependency removed (`delete-link`). Each becomes one `GanttChange` through `onChange` — `{ type: 'dates', id, start, end }`, `{ type: 'progress', id, progress }`, `{ type: 'add-dependency', from, to, dependencyType }`, `{ type: 'remove-dependency', id }` — and SVAR is rebuilt from the application's rows, so a drag the application has not accepted goes back. A double click opens Change dates…. SVAR's own keys (Backspace deletes, Ctrl+C/X/V/D) and its add / delete / copy / move / indent / split actions are blocked. `applyGanttChange` is what an application may do (phases are not recomputed, dependants not moved: scheduling is the application's; example AA lets each phase span its tasks). A phase's dates are the application's: it has no Change menu and its bar does not drag.
  5. **Every drag has another way (WCAG 2.5.7):** each task and milestone row has a Change menu (`Change Floors 3–4`, a 28px button) — Move… (a new start; the length stays, "Ends on …"), Change dates… (a range; a milestone's one date), Set progress… (0–100, a decimal string), Dependencies… (what it comes after, each with Remove; a task to add, chosen from the ones that make no loop (`dependencyCandidates`), and how, in words: "Starts when it finishes", "Starts when it starts", "Finishes when it finishes", "Finishes when it starts"). Each dialog is titled by its action with the row bold under it (D22). Every reported change is announced politely. Moving a bar with Enter and the arrow keys (as Diagram) is not built: the dialogs are the keyboard way.
  6. **The table is the accessible plan.** At the start of the timeline, a table (`role="table"`, named by `label`) with one row per bar at the same 44px: the row header names the row in full ("Task: Floors 3–4, in Structure, 05.10.2026. – 30.10.2026., 40% done, Crew Ilić, At risk, After: Floors 1–2"); visibly the name (cut with "…" when long, the full name in `title`), its dates and who does it, its state, its progress and, when the application gives them, a phase's budget and what was spent with the application's verdict ("Over budget", warning). Every bar carries the same name for assistive technology (visually hidden, through `taskTemplate`). The chart is one scrolling region ("Timeline: Residential building Liman 4", Tab stop, arrows scroll it, described by how to use it); SVAR's own focusable layout box is taken out of the Tab order. The header rows of the table and the time scale stay below the shell while the page scrolls (D21, `useStickyHead`'s `--liro-head-shift` on both).
  7. **The one "now" marker is ours (D25).** SVAR's markers are a PRO feature (the MIT store empties them). Gantt draws NowMarker into SVAR's chart area from the application's `now` ("HH:mm" of the provider's `today`, a local date-time or an instant shown in the provider's `timeZone`), at the x SVAR gives a date (its own scale's `diff`, times the column width it settled on — SVAR widens the columns of a short plan to fill the chart), plus the part of the day passed (`nowPosition`). Named "Now, 14.10.2026. 09:40". The chart opens scrolled so that now is in view.
  8. **Look (D17, tokens only):** a task is a bar in its tone (neutral unless the application gives a state: "At risk" warning), its progress a 4px line along its bottom in the text colour (never a fill under the text, so the text keeps its contrast); a phase a slim `surface.inverse` bar with its progress in `surface.raised`; a milestone a `text.primary` diamond with its name after it; dependencies `border.control` lines (3:1), strong on hover; the chosen row `surface.selected` with the 3px `border.selected` bar, never blue.
  9. **Scales: months (default) and days.** Labels from the provider (D11): "Oct", "October 2026" through `format.monthName`, years and day numbers as digits. **No weeks scale:** SVAR places weeks by its own locale's first day, not the provider's (D11); days and months need none.
  10. **Right to left: the timeline is mirrored** (SVAR has no right-to-left). The chart is drawn with `transform: scaleX(-1)` so time runs from the leading edge beside the table (which stands at the start), and every text in it is turned back (`data-gantt-text`, the scale's labels). **Dragging is off in right-to-left**: SVAR measures the pointer in physical pixels, so a mirrored drag would move the bar the wrong way; the rows' dialogs edit instead. The table, the list and the dialogs follow the page's direction.
  11. **Phones** (below 48em, or `screen="phone"`): the plan opens as the list by phase (each phase a card: name, dates, progress, budget and spent, state; its tasks and milestones with dates, progress, who and "After: …"); "Timeline" shows the chart alone, read-only, scrolling sideways inside its card (D19). Editing says "Open this plan on a larger screen to change it." The list is the plan as text on every width ("List").
  12. **States:** `loading` (skeleton rows, `aria-busy`), no rows ("No tasks yet"), `error` (the message and Try again).
