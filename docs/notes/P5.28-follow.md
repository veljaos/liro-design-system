## 1. Decision entries (for `docs/decisions.md`)

- **2026-10-13 — The statutory grid on the shared sticky mechanism (P5.28 item 4).** The documents
  helper made StatutoryFormPage's header stick under the shell while the grid fits its card
  (`thead` at `top-[var(--liro-shell-top,0px)]`) and, when it does not fit, turned the grid into a
  bounded region (at most the viewport's height under the shell) that scrolled both ways, its header
  sticky at the region's own top. It now uses `components/sticky-head.ts` as AttendanceGrid does:
  the grid's box is always a sideways scroller (`overflow-x-auto`, `STICKY_CLEARANCE`), the `thead`
  carries `STICKY_HEAD` and `data-sticky-head`, `useStickyHead` moves it below the shell while the
  **page** scrolls, the corner cell is `sticky start-0` with `data-sticky-start`, the rows' number
  and label cells `sticky start-0 z-[5]` on surface.raised. **Kept from the documents helper**
  (equivalent or better): the region is named and focusable only while it overflows
  (`role="region"`, the part's title, `tabIndex=0`, `data-overflowing`), `border-separate`, group
  headings that stay at the start while scrolling sideways (`--liro-grid-width`). **Replaced:** the
  bounded height. Why: with a bounded region a long part had two vertical scrollbars (the page's
  and the grid's), the wheel stopped scrolling the page inside the grid, and the header stuck to the
  region instead of the shell — the shared mechanism keeps one page scroll and the header under the
  shell whether the grid fits or not, which is what the owner asked for ("like the gradebook").
  **`STICKY_HEAD` on the `thead`, not on each cell:** the form has two header rows (a group over
  its sub-columns); moving the group keeps them together (cells at `top-0` would put the second
  row on the first if the region ever scrolled down). The grid's own controls (entered fields,
  pencils, source buttons) get the same scroll margins as the cells (a field reached by the
  keyboard under the header is scrolled clear of it, WCAG 2.4.11); on phones (one card per row,
  nothing sticky) a focused field is scrolled clear of the shell. Stories (interaction):
  "Thirty-two rows under the shell, interaction" (desktop, a narrow card: the header and corner
  stay right below a 56px shell after the page scrolled 400px past the grid's top, a field under
  the header is scrolled clear when focused, the number and label column stays while the grid
  scrolls sideways) and "Thirty-two rows under the shell, phone, interaction" (390 × 720 frame: no
  sideways scroll, 32 row cards, a field focused under the shell is scrolled clear). The 32-row
  part is an illustrative input-tax record in the story file.
- **2026-10-13 — Every DataTable's header stays below the shell by default (P5.28 item 4).**
  `stickyHeader` now defaults to **true** (was false): every DataTable on a page — ListPage's and
  RegisterPage's tables, ClockRecordList, WorkingTimeBalance, ImportWizard's columns table, the
  examples' document lines, members, roles, invitations, absences — keeps its header below the
  shell while the page scrolls, with no prop to remember. At rest nothing moves (the shift is 0).
  `stickyHeader={false}` remains for a table whose header must not move (none in the library).
  ListPage and RegisterPage therefore pass nothing (a ListPage default through context was
  considered and dropped: the default covers every table, not only those in a list card).
  DataTable's corner cells now carry `data-sticky-start` (with a selection column, both), so the
  keyboard's scroll margin clears the sticky first column in a card; the hook measures the cover
  from the region's start edge to the farthest marked cell (`startCover`, tested), so a selection
  column before the first column counts. Alpha behaviour change (no API change).
- **2026-10-13 — PortalShell publishes `--liro-shell-top` (P5.28 item 4).** As AppShell's: a
  ResizeObserver on the sticky header writes its height on the shell root, so a table's header, a
  phone's totals or anything sticky in a portal's page stands below the portal's header. Checked in
  "Patient portal" and "Patient portal, phone".
- **2026-10-13 — TreeTable's header below the shell (P5.28 item 4).** The header row was sticky
  only when windowed (`maxHeight`); now always `STICKY_HEAD` with `useStickyHead`, the header
  rowgroup `data-sticky-head`, the region `STICKY_CLEARANCE` plus a scroll margin on the focusable
  rows (`[role=row][tabindex]`). The tree column is **not** sticky at the start: TreeTable has no
  card mode, so its surface is not known (the rows are transparent, the hover and selection on the
  row), and no consumer is wider than its box. Story: "Seventy rows under the shell, interaction".
- **2026-10-13 — "Go to" in the statutory checks is a neutral secondary button (P5.28 item 7).**
  It was link-blue text on the toned rules Alert; now `Button family="neutral"
emphasis="secondary" icon={LocateFixed}`, as the diagram's problems list. The source drill-down
  Drawer names what it shows and the row (P5.28 item 6): title "Source documents"
  (`messages['statutory.sources']`), `subject` "1.1.1 Промет …" (bold, its own line, the form's
  `lang` on the label), description column · period as before.
