## Decision entries (for `docs/decisions.md`, section "Accounting workflows (P5.31–P5.39)" or a
new one "Files and folders (P5.43)")

- **2026-10-14 — FileBrowser: a company's files and folders are one template (P5.43).** Design
  system only: folders, files, owners, sizes, permissions, storage, versions, sharing, signing
  and retention are the application's, through props; the browser shows them, takes the files the
  user chooses and reports every action. It never sorts, filters, searches or adds up sizes (D4):
  the entries arrive in the order to show. **Desktop:** the folder's path as Breadcrumbs (every
  folder has an address, B.8), the location's name as the page's h1 (PageHeader); a start column
  (256px, "Hide folders" / "Show folders") with the quick places (Recent, Favourites, Shared with
  me, Trash: the application's, the current one neutral with the selected bar, D17), the folder
  tree (TreeView, one choice) and the storage used against the quota (the application's
  UsageMeter); one card with FilterBar (search at the start, "Type" and the application's
  filters, at the end Hide folders, List / Grid, Details, the application's own, New folder,
  Upload — the main one last), while searching "Search in: <folder> / Everywhere" (pressed chips,
  neutral), the uploads (AttachmentList with P5.5's states and progress per file, "2 of 5
  uploaded", Clear), and the content: the list (DataTable: name with its icon, marks — shared,
  favourite, the application's badges — location and upload state; owner; modified; size or a
  folder's items through `format`; linked to, as links; the application's columns after them;
  sorted by the headers) or the grid (FileGrid). The details column (320px, FileDetails) at the
  end while open. **States:** loading (skeleton rows or tiles), the application's error with Try
  again, an empty folder ("This folder is empty", Upload), nothing found ("No files match",
  "Search everywhere"), no access (Lock, "You do not have access to this folder" with the
  application's reason and way on), offline (a neutral Alert; Upload and New folder unavailable
  with "Not available while offline.").
- **2026-10-14 — Upload: FileDropzone in a dialog, the card as the drop shortcut (P5.43).**
  "Upload" opens a dialog titled by the action with the folder bold under it (D22): FileDropzone
  (the accepted types and the size limit shown before choosing; "Take a photo" on phones,
  `camera`) and, on desktops, "Choose a folder" (a whole folder; each file keeps its path,
  `UploadedFile`, `withPaths`). Files dropped from the computer anywhere on the card upload too —
  the card takes the neutral selection and says "Drop the files to upload them to <folder>";
  dropped folders are read through (`webkitGetAsEntry`) with their paths. Every file is checked
  again (`checkFiles`, P5.5) and the rejected ones are named under the toolbar in an always-present
  `role="alert"`. Progress per file is AttachmentList's (it already showed it): no new upload list.
- **2026-10-14 — Moving by drag has the menu's way (P5.43, WCAG 2.5.7).** A row or a tile dragged
  onto a folder — a folder row, a folder tile, a folder in the tree — is reported with
  `onMove(ids, folderId)`: the dragged item, or the whole selection when it is in it. The
  dragging rule ("Launchpad dragging is live"): pointer events, never HTML5 drag and drop; a mouse
  after 4px, a touch after a 250ms press; a neutral chip "Moving 3 items" / "Move into Permits"
  follows the pointer (shadow lg, border.strong, positioned from the inline start), the folder
  under it takes surface.selected with a 2px border.selected inset frame and is announced
  politely; never a moved folder, a folder inside one, or the folder they are in
  (`canDropInto`, `folderPath`); Escape cancels ("Move cancelled."), the click after a drag opens
  nothing. The keyboard's and the menu's way is the application's "Move to…" in each item's menu
  and on the selection: **FolderPickerDialog** (the action as title, what is moved as subject, a
  TreeView with one choice; the moved folders and their folders cannot be chosen and say why,
  `blockedFolders`, `pickerTree`; "Destination: Company documents / Site documentation / Permits"
  or why the button cannot be used — nothing chosen, already there — through UnavailableAction's
  `reasonId`). Phones have no drag.
- **2026-10-14 — FileGrid: thumbnails, checked neutrally (P5.43).** Tiles (radius lg, 12px
  padding) with a 4:3 picture (the application's thumbnail, decorative, or the family's 40px icon
  on surface.sunken), the name in two lines, the marks, the facts. A checked tile is
  surface.selected with a border.selected border (D17); the checkbox in the top start corner is
  the pointer's way (blue only when checked). One tab stop: arrows by the measured columns
  (`launchpadArrowTarget`, mirrored in right-to-left), Home / End, Space checks, Shift+arrows
  extend from the last tile checked (`selectRange`), Ctrl/Cmd+A checks all, Enter opens; Tab
  reaches the focused tile's menu (28px, "Actions: <name>"); Ctrl/Cmd+click and Shift+click.
- **2026-10-14 — NameConflictDialog (P5.43).** "A file with this name exists" with the name bold
  under it; the folder in words; the two files side by side ("In the folder" / "Being uploaded":
  size and when through `format`, who owns the one there); Replace / Keep both / Skip as radios
  with what each does — Keep both's new name is the application's (`keepBothName`); Replace can be
  unavailable with the application's reason ("Signed documents cannot be replaced; upload it as a
  new version."). Keep both is chosen at first (nothing is lost). With more waiting: "Conflict 1
  of 3" and "Apply to all 3 conflicts" (`resolveConflicts`: a conflict that cannot be replaced
  keeps its own question). Each Continue reports its answers and the next question starts fresh.
- **2026-10-14 — ShareDialog (P5.43).** "Share" with the item bold under it: add people, roles or
  a client's portal (one ComboboxField over the application's candidates, the level — the
  application's "View" / "Edit" —, Add); who has access (a neutral icon by kind, name, detail,
  where the access comes from, "Owner", a fixed access with its level and reason, otherwise a
  level select and a 28px "Remove access: <name>" — reversible, so it does not ask); the link
  (none: what a link does and "Create link"; a link: its address with ShareLinks' Copy link,
  "Expires" — a day not after today is an error, `expiresTooSoon`, never reported —, "Password"
  as a switch with a PasswordField that is used once and not kept, "Revoke link" asking first).
  `linkUnavailable` / `addUnavailable` say why ("Employee files are never shared by link.").
  Every change is reported as it is made; "Done" closes. The QR code was not added (optional).
- **2026-10-14 — VersionList, FilePreview, FileDetails, FileNameDialog (P5.43).** VersionList:
  newest first, "Current" neutral badge, when / who / size, the application's note; Download
  (document family) and Restore (caution family, asks with the version as subject); "Upload a new
  version"; restore and upload unavailable with the application's reason. FilePreview: a
  full-screen sheet on every width — the name as title, the application's line, "3 of 12",
  Previous / Next file (and ArrowLeft / ArrowRight by the reading direction outside the viewer),
  Download, the application's actions; the viewer is the application's (DocumentFrame for PDFs and
  office files, PageViewer for photos and scans — the paper is light and never mirrored, which
  suits a photo too); `unavailable` says "This file cannot be previewed" with Download. FileDetails:
  icon and name (h2) with marks, actions, then SidePanels — Details (type, size, owner, created,
  modified, location, the retention label exactly in the application's words with an Archive icon,
  tags as neutral badges, the application's facts), Linked to (links), Signing (the application's
  SignerList: Liro Bridge signs), Versions, Sharing, Activity. FileNameDialog: one name for a new
  folder or a rename; empty says "Enter a name."; the application's check returns its words.
- **2026-10-14 — Phones (P5.43).** The list only (no grid, no drag, no tree): folders as rows (56px,
  icon, name, marks, facts), a press opens; each row a 44px "Actions: <name>" that opens its
  actions in a bottom sheet (Dialog, which is a sheet on phones: "Actions" with the item as
  subject, 44px rows, destructive in danger fg); the path is "Back to <parent>" beside the h1;
  the quick places as pressed chips; Upload as the bottom-sheet dialog with "Take a photo" and
  "Choose files"; the details in an end Drawer; the preview full screen.
- **2026-10-14 — An entry's upload state (P5.43).** A file still uploading or being checked shows
  P5.5's words under its name (AttachmentList's messages: uploading, checking for viruses,
  blocked, not uploaded), so the client's photo "IMG_2051.jpg" reads "Checking for viruses…" in
  the accountant's folder.
