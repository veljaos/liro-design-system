## Lint

- **2026-09-24 — Inline configuration is off.** `linterOptions.noInlineConfig: true`, `reportUnusedDisableDirectives: "error"` and `--max-warnings 0`: an `eslint-disable` comment produces a warning, and a warning fails the run. Exceptions go into `eslint.config.mjs`, where they are visible and protected (BUILD-PLAN rule 10).
- **2026-09-24 — TypeScript escape hatches.** `@ts-ignore`, `@ts-nocheck` and `@ts-expect-error` are errors outside test files. Test files (`*.test.ts(x)`, `*.spec.ts(x)`, `__tests__/`) may use `@ts-expect-error` with a description, to prove that a wrong call does not compile.
- **2026-09-24 — Line endings.** `.gitattributes` forces LF so Prettier gives the same result on Windows and on the Linux CI runner.
- **2026-09-25 — Colour and direction rules (P1.1).** `@veljaos/eslint-config` ships the plugin `liro` with `liro/no-raw-colors` and `liro/logical-properties`, both in its default configuration. They read every string literal, every piece of a template literal and every inline JSX `style` object. `no-raw-colors` reports Tailwind palette utilities (`bg-red-500`, `ring-offset-white`), hex literals, colour functions (`rgb(…)`, `oklch(…)`, `color-mix(…)`), named colours in `style`, and the `dark:` variant: themes switch through the tokens, and Tailwind's `dark:` follows the operating system, not `LiroProvider`. `logical-properties` reports `ml-`/`mr-`/`pl-`/`pr-`, `left-`/`right-`, `text-left`/`text-right`, `float-`/`clear-left|right`, `border-l`/`border-r`, `rounded-l|r|tl|tr|bl|br`, and physical `style` properties. Fixture tests: RuleTester cases plus `packages/eslint-config/fixtures/*.tsx`, whose `expect:` comments name the reports of each line. Limits: CSS files are not linted, and a string such as `"#add"` looks like a hex colour and is reported.
- **2026-09-25 — Radix under both names.** The import rule for consumers now also forbids `radix-ui` and `radix-ui/*`: Radix ships as the single package `radix-ui` as well as `@radix-ui/*`, and `@veljaos/ui` uses the single package from P1.5 on (AGENTS.md D10).
- **2026-09-25 — The repository lints itself with the shipped rules.** `eslint.config.mjs` imports `packages/eslint-config/src/index.ts` directly, because lint runs before the build in CI. Node 24 runs it by stripping types, so the package's own imports name `.ts` files (`allowImportingTsExtensions`) and use only erasable syntax (`erasableSyntaxOnly`). Exempt: `packages/tokens/**` (colour values live there) and `packages/eslint-config/src/**` (the rules and their tests quote forbidden classes); the fixtures are ignored.

## Typography and fonts

- **2026-09-25 — Fonts ship with @veljaos/tokens (P1.2).** `dist/fonts.css` holds every `@font-face` of the Fontsource `wght` stylesheets, unchanged except the file paths, and `tokens.css` imports it first, so consumers keep two CSS imports. Every face keeps its `unicode-range`: a browser downloads a subset only when the page has a character in it (the CJK families are split into about a hundred subsets each). The package grows to about 16 MB of font files; a page downloads only what its text needs. Families keep Fontsource's names (`Noto Sans Variable`, …), so they never collide with a font installed on the device.
- **2026-09-25 — One interface stack, CJK order by language.** `--liro-font-sans` is Noto Sans (Latin, Cyrillic, Greek), then Noto Sans Arabic and Hebrew, then the CJK families: SC, TC, JP by default; TC first for `zh-Hant`, `zh-TW`, `zh-HK`, `zh-MO`; JP first for `ja`. Han characters are shared but drawn differently, so `lang` decides. The variable is redeclared under `:lang()`, and `font-family` is set again on every element with `lang`, so the element with the attribute and everything inside it use the right order.
- **2026-09-25 — Base typography in `@layer base`.** `tokens.css` sets `font-family`, `line-height` and `letter-spacing` on `:root`, on every `[data-liro-theme]` and on every `[lang]`, and the body size (`--liro-font-size-md`, 14px) on `[data-liro-theme]` only: the root font size stays, so `rem` and Tailwind's spacing do not change. The rules sit in the lowest layer and have zero specificity (`:where`), so any utility or application style wins.
- **2026-09-25 — Per-script adjustment.** Arabic script (`ar`, `fa`, `ur`) and CJK (`ja`, `zh`) body text takes A.5's relaxed line height (1.6) and no letter spacing: negative spacing breaks the joining of Arabic letters, and CJK is set solid. The A.5 values stay as they are (`--liro-leading-base`, `--liro-tracking-body`); the adjustable ones are `--liro-leading-body`, `--liro-tracking-body-text` and `--liro-tracking-heading-text`, which the Tailwind sizes and headings use.
- **2026-09-25 — Tailwind type scale.** Tailwind's fonts, sizes, weights, line heights and letter spacing are removed and replaced: `font-sans|brand|mono`; `text-xs … text-xl` (with the body line height and spacing of the script); `text-h1 … text-h6` (size, line height, semibold, heading spacing); `font-regular|medium|semibold|bold` (A.5 calls 400 "regular", so `font-normal` no longer exists); `leading-tight|base|relaxed`; `tracking-heading|body|caps`. Tabular digits: Tailwind's `tabular-nums` (Noto Sans has the `tnum` feature).
- **2026-09-25 — Brand face.** Space Grotesk, then Inter, then the interface stack. Both are shipped: Space Grotesk has no Cyrillic or Greek, so a Cyrillic wordmark or status page falls back to Inter. Monospace (JetBrains Mono, Cascadia Code, system monospace) is not shipped: it is a stack of fonts the device may have. (Replaced on 2026-10-01: JetBrains Mono is shipped, see "Monospace is shipped".)
- **2026-10-01 — Monospace is shipped (P3.0a, decided by the owner).** `@veljaos/tokens` ships JetBrains Mono, the first family of A.5's monospace stack, from Fontsource as `JetBrains Mono Variable` (weights 100–800, one variable file per subset: Latin, Latin Extended, Cyrillic, Cyrillic Extended, Greek, Vietnamese), so variable names, case numbers and shortcut keys look the same on every device and in the tests. `--liro-font-mono` is now `'JetBrains Mono Variable', 'JetBrains Mono', 'Cascadia Code', ui-monospace, SFMono-Regular, Menlo, Consolas, monospace`. The reason is "Local baselines match CI" under CI: the system monospace made screenshots depend on timing.
- **2026-09-25 — The lang rule.** Text whose language differs from the page carries `lang`: `langAttribute(textLang, pageLocale)` and `useLangAttribute(textLang)` in `@veljaos/ui` return `{ lang }` when the language or the script differs (`sr-Cyrl` on a `sr-Latn` page, `ja` on a `zh-Hans` page), and nothing for a region alone. Serbian without a script counts as Latin (B.1). With `lang`, the browser applies the font's Serbian forms to Cyrillic italics (б, г, д, п, т) and the JP family to Japanese. Text in the other direction also needs `dir`; the Scripts story sets it on each sample.

## Buttons

- **2026-09-25 — Button weights (decided by the owner).** Carried over from the previous Design System, which was built on Mantine:
  - **primary emphasis = "filled":** the family colour as background, white text (`text.onAccent`); gray and orange fill with shade 7. Hover one shade darker, press two (blue 6 → 7 → 8; gray and orange 7 → 8 → 9).
  - **secondary emphasis = "light":** the family's subtle tint as background (blue: `brand.subtle` = blue0) with the family's text colour, no border; hover goes to the stronger tint (`brand.subtleHover` = blue1). **Exception:** the neutral family's secondary is **"default"**: raised surface, `border.default` (gray3) border, `text.primary` text; hover `surface.hover`.
  - **menu emphasis = "subtle":** no background, no border, the family's text colour; a background appears only on hover (`surface.hover` for neutral, the family's subtle tint otherwise). A menu-emphasis button standing alone outside a menu looks the same.
  - **Status badge** (P1.4): the tone's fg on the tone's bg; no border unless `withBorder` (1px, the tone's border colour); radius xs (2px); padding 2px 6px; size xs (12px); weight 600; line height 1.4; 4px between icon and label; never wraps.
- **2026-09-25 — Hover text one shade stronger (decided by the owner).** The contrast script measured the family's text on the stronger tint below 4.5:1: 4.08–4.29 in the light theme (primary, verify, document, positive) and 4.28/4.31 in the dark theme on the overlay surface (primary, destructive). On hover, light and subtle buttons therefore also take the stronger text, `fgHover`: one shade darker in light (7 → 8; caution 8 → 9), one lighter in dark (blue 4 → 3, the others 3 → 2). The tints stay exactly as decided.
- **2026-09-25 — Family tokens derived from the brand pattern.** A.6 gives only the filled shade. The other family colours follow the established brand tokens: the tint is shade 0 and its hover shade 1 in light, and the fill colour at 0.16 and 0.26 in dark (as `brand.subtle`); the text colour is `text.brand` for primary and the matching status tone's `fg` for the others (positive ↔ success, destructive ↔ danger, caution ↔ warning, document ↔ premium, neutral ↔ `text.primary`; verify, which has no tone, as the tones: teal 7 / teal 3). They are the `--liro-family-<family>-*` meanings and the `bg-family-*`, `text-family-*` utilities. `packages/tokens/src/contrast.ts` measures every text-on-background pair of every family and tone, in both themes, composited over every opaque surface (B.6); `pnpm build` fails below 4.5:1.
- **2026-09-25 — Button API.** `Button` takes `intent`, or `family` + `icon`; `label` is required in both, because the Design System has no text of its own (an intent brings family, emphasis, icon and confirmation, not words). No `color`, no `variant`: the types reject them (tested with `@ts-expect-error`). A family without an intent defaults to secondary emphasis, so a screen does not collect filled buttons by accident. `IconButton` takes the same props and draws only the icon; `CompactIconButton` makes the family optional (default neutral) and defaults to menu (subtle) emphasis, as Mantine's ActionIcon. Both use `label` as the accessible name and title. The confirmation of `delete` (and module actions) is P2.4; the button carries `data-confirms` until then. The disabled reason is shown by the unavailable action of P2.7.
- **2026-09-25 — Button sizes (decided by the owner; values read from Mantine).** The previous Design System used Mantine's theme `defaultRadius: 'md'` and Button size `'sm'`; icon-only buttons were ActionIcon with the default size `'md'`, neutral and subtle. Source: the npm package `@mantine/core` 9.6.2, `styles/Button.css`, `styles/ActionIcon.css` and `styles/default-css-variables.css`:
  - `--button-height-sm: 36px` (our `--liro-size-control-height`); `--button-padding-x-sm: 18px`; with a left section (the icon every Liro button has), `padding-inline-start: calc(var(--button-padding-x) / 1.5)` = 12px; the section's `margin-inline-end: var(--mantine-spacing-xs)` = 10px between icon and label; `font-weight: var(--mantine-font-weight-medium)` = 600; `line-height: 1`; `border: 1px solid transparent`; `border-radius: var(--mantine-radius-default)` = radius md, 8px.
  - Font size: the owner's theme `sm` = 13px (A.5 `sm`; Mantine's own default `sm` is 14px).
  - Disabled, every variant: `border: 1px solid transparent`, `background: var(--mantine-color-disabled)`, `color: var(--mantine-color-disabled-color)`; here `surface.disabled` and `text.disabled`.
  - ActionIcon: `--ai-size-md: 28px`, the same default radius and transparent border.
  - Icon size (from the owner, the old ActionButton source; not in Mantine's CSS): 15px in a button with text.
  - Button therefore has no `size` prop: a second size comes when a screen needs one and its values are known.
- **2026-09-25 — Two icon-only buttons (decided by the owner, from the old ActionButton, P1.3a).** An action without visible text is **`IconButton`**: the normal 36px button (control height) with 8px horizontal padding and a 16px icon, the label as its `aria-label` and title; family and emphasis as for `Button` (an intent's own emphasis, secondary for a family). The 28px Mantine ActionIcon is **`CompactIconButton`**: neutral and subtle (menu emphasis) by default, 16px icon, used **only in tight places** such as table row menus and close buttons. Both keep the target size above 24×24px.
- **2026-09-25 — Direction arrows mirror.** The `back` (ArrowLeft) and `next` (ArrowRight) icons are drawn mirrored in right-to-left, so "next" points forward in reading order (A.6 marks `back`; `next` is the same class of icon, B.7).
- **2026-09-25 — StatusBadge and toneFor (P1.4).** `StatusBadge` takes `label` and `tone`, with optional `withBorder` and `icon`, in the badge weights above; line height 1.4 is an arbitrary value (`leading-[1.4]`) because A.5 has no 1.4 and the owner gave it exactly. `toneFor(status, map, fallback = 'neutral')` reads the tone from a map the application gives as data; an unknown status (including inherited names such as `toString`) gets the fallback. The example map of A.7 lives only in the StatusBadge stories. Every tone's fg on its bg is measured by the contrast script in both themes over every surface (lowest: dark danger on the overlay surface, 4.66).
- **2026-09-29 — Long labels wrap (decided by the owner, P2.7d).** A button label is never cut with "…". It stays on one line while it fits; where it does not, it wraps with each line centred and the button grows in height from its minimum (36px, 30px for the small bar buttons). Two lines is the normal limit; a third appears only when even two do not fit (the owner, asked about that case: text is never hidden). A text button shrinks to its container (`min-w-0`, `max-w-full`), so it wraps only when it is alone on its line and still too wide; its line height is the font size plus 4px (`leading-[calc(1em+4px)]`), so two lines do not touch and a single line stays on exactly the same pixels (1.25 moved it by one). A text button is `h-fit`, so it is never stretched to the height of a flex row (a minimum height alone would let it stretch); the chevron half of SplitAction takes the height of the main half. IconButton and CompactIconButton keep their fixed size. In `ActionGroup` and `BulkActionBar` the actions before the main one move into the "More" menu first (BulkActionBar gained the menu here, with a 28px "More" button and the same one confirmation for a chosen action), so wrapping is the last resort; both measure the unwrapped widths in an invisible copy of the row.

## Tokens

- **2026-09-25 — One source (P1.1).** Every value and meaning is in `packages/tokens/src/tokens.ts`. - **2026-09-25 — Three layers in CSS.** Values (`--liro-blue-6`, `--liro-space-md`, …) are declared once on `:root`. Meanings (`--liro-surface-page`, `--liro-status-danger-fg`, …) are declared per theme and refer to values with `var()`; the light block also matches `:root`, so the light theme applies without a provider. Any element may carry `data-liro-theme`, so both themes can appear on one page (the Tokens page shows them side by side). The ramps are not Tailwind utilities: components cannot reach a value.
- **2026-09-25 — The Tailwind theme removes Tailwind's own look.** `theme.css` resets `--color-*`, `--radius-*`, `--shadow-*`, `--ease-*` and `--breakpoint-*` and puts the Liro ones in their place, so `bg-red-500` or `rounded-2xl` do not exist, and the breakpoints are A.4's (`md` = 62em). Utilities refer to the `--liro-*` variables through `@theme inline`, so each element resolves its own theme.
- **2026-09-25 — Each meaning reaches only the utilities it is for.** Tailwind 4 reads `--text-color-*` for `text-*`, `--background-color-*` for `bg-*` and `--border-color-*` for `border-*` and `divide-*` before the shared `--color-*`. Text meanings are `text-primary`, `text-secondary`, `text-tertiary`, `text-disabled`, `text-on-accent`, `text-brand`, `text-link`; surfaces `bg-surface-*`; borders `border-default|strong|subtle|brand|focus`, with `outline-focus` and `ring-focus`; brand backgrounds `bg-brand-solid|solid-hover|solid-active|subtle|subtle-hover` with `text-brand-on-solid`, and `brand-accent` for any utility; tones `text-status-<tone>-fg`, `bg-status-<tone>-bg`, `border-status-<tone>-border`, and `bg-|fill-|stroke-status-<tone>-solid`. So `text-brand-solid` and `text-status-danger-solid` do not exist (A.2: `brand.solid` is a background; B.6: `solid` is never text).
- **2026-09-25 — shadcn/ui variables map onto Liro meanings.** `--background` page, `--foreground` text primary, `--card` raised, `--popover` overlay, `--primary` brand solid (on it brand onSolid), `--secondary` and `--muted` sunken, `--muted-foreground` text secondary, `--accent` hover surface, `--destructive` danger solid, `--border` border default, `--input` border strong, `--ring` border focus, `--radius` radius md. They are declared on `:root` and on every themed element, so each resolves in its own theme. Because text meanings win for `text-*`, `text-primary` is the primary text colour (not shadcn's brand blue), `text-secondary` the secondary text colour, and `text-destructive` the danger text colour; P2.1 adapts the few primitives that use `text-primary` or `text-white`.
- **2026-09-25 — Spacing uses Tailwind's scale.** With `--spacing: 0.25rem`, `p-1` … `p-16` are exactly A.3's 4 … 64px. Named spacing (`p-xs`) was not added: `max-w-xs` and the other `max-w-*` utilities would read `--spacing-xs` before the container sizes. `--liro-space-*` exist for CSS. Sizes are utilities: `h-header`, `h-control`, `h-control-sm`, `max-w-content`. Layers are variables only: `z-(--liro-layer-modal)`.
- **2026-09-25 — Motion.** The default `transition` uses `--liro-duration-base` and `--liro-ease-standard`; `ease-standard|decelerate|accelerate` exist. With `prefers-reduced-motion: reduce`, every `--liro-duration-*` is 0ms.
- **2026-09-25 — tokens.json** has `color` (ramps and common), `meaning.light|dark` (every meaning and tone, resolved to a colour), `space`, `radius`, `shadow.light|dark`, `motion`, `breakpoint`, `size` and `layer`, for renderers without CSS.

- **2026-09-30 — The visual test fails on a failed story (P3.0; closes the open item of 2026-09-29).** `tests/visual.spec.ts` now checks the story's outcome first, exactly as the story test does (no errors, status "success"), and takes and compares the screenshot only after that. A failed interaction fails the visual test with its own error, and no picture is written, even with `--update-snapshots` (tested locally by breaking the MonthField "Open" story's play function: the test failed on the interaction and wrote no image).

- **2026-10-06 — What a visual test does not see (P4.0).** `toHaveScreenshot` compares with `maxDiffPixels: 0` but Playwright's per-pixel colour threshold (default 0.2, a perceptual distance): a pixel counts as different only beyond it. Found when a search button changed from 35.5px to 30px high: its light grey border moved by 3px, every moved pixel stayed under the threshold, the test passed and `--update-snapshots=changed` wrote nothing (proved in the CI image: the screenshot differs from the baseline, the comparison passes). So a change of a faint line alone can leave a baseline stale; when a change is meant to move only such lines, regenerate those baselines with `--update-snapshots=all` for the stories concerned. The threshold is a protected setting and is unchanged.
- **2026-10-06 — Baselines on CI's machines (P4.0).** Locally, `scripts/update-baselines.mjs` takes 30–40 minutes on the owner's machine. The workflow `Baselines` (`.github/workflows/baselines.yml`) does the same in the same pinned image on twelve machines: one job builds Storybook, twelve run `test:visual --update-snapshots=changed --shard=N/12`, and each part collects the images Playwright wrote (newer than a marker file taken before the run), so only new and changed images return; a last job joins them into one artifact `baselines` (7 days) and lists them in the run's summary. It starts on a push to a `bp/*` branch whose commit message contains `[baselines]` — the agent needs no permission beyond pushing its branch — or by hand from the Actions tab. A push without `[baselines]` also starts the workflow, which then does nothing; such a run has a concurrency group of its own (its commit), so it never cancels an update in progress (the first version did: two update runs were cancelled by the next ordinary push). It never commits: a commit pushed with the workflow's token would start no CI run, so the pull request's head would carry no checks; the images are reviewed and committed by hand (AGENTS.md, "How to refresh visual baselines").
- **2026-09-30 — Open item: local baselines differ from CI on one page.** `node scripts/update-baselines.mjs` on the owner's Windows machine (Docker Desktop 29.6.2, the pinned image) renders "Foundations/Tokens / Meanings in both themes" 77px shorter (4,185px) than CI does (4,262px, the committed baseline, which CI passes): the first 4,185 rows of pixels are identical, and `main` without any change gives the same 4,185px locally, so the difference comes from the local environment, not from code. The faster way of working (P3.0) relies on local baselines matching CI; until this is understood, a baseline run that changes that page is not committed (P3.1 and P3.2 left those four images out). **To investigate before P3.4** (decided by the owner). Closed on 2026-10-01, next entry.
- **2026-10-01 — Local baselines match CI (P3.0a; closes the open item of 2026-09-30).** **Cause: the system monospace font, not the machine.** The Tokens page writes variable names in `font-mono`, and nothing in A.5's stack existed in the Playwright image, so the generic `monospace` decided. In that image fontconfig answers `monospace` with WenQuanYi Zen Hei Mono (a CJK font of the image), and Chromium used it for the first layout; after the first full-page screenshot (which re-sends the page's settings to the renderer) Chromium used its own Monospace preference, Liberation Mono, and kept it. The two fonts have different line metrics: each of the 40 table rows whose variable name wraps onto two lines grows from 48 to 50px, so the page grows from 4,185 to 4,262px after the first screenshot (measured: page height and the font of one cell via the DevTools protocol, before and after a screenshot). `toHaveScreenshot` takes screenshots until two in a row are equal: on a quiet machine the second and third (4,262px) agree, which is what CI saw (4-core runners, 2 Playwright workers). Locally 8 workers run on 16 threads; a 4,262px capture then takes over two seconds, the 5-second limit runs out between alternating sizes, and an update run wrote the first, 4,185px picture. **Not the cause** (checked): the image digest (the same), Node (24.21.0 in both), the viewport (1280 × 720, scale 1 in both), the operating system (both are the same Linux image; Docker Desktop's kernel only hosts it), and caches (each run installs and builds from scratch). The same test alone in the local container passed against the CI baseline; with 8 workers and 8 repeats it failed in most runs, and with a concrete monospace font (Liberation Mono, as an experiment in a throwaway copy) all 32 runs passed. **Fix:** JetBrains Mono is shipped (Typography, "Monospace is shipped"), so no story depends on the image's fonts or on Chromium's font settings; every story with monospace text got new baselines. **Noticed on the way, not changed:** the Storybook decorator's page wrapper is `min-h-dvh` with `p-4` in content-box sizing, so a short story is always 752px (the 720px viewport plus 32px) — stable, because it does not depend on timing, but it changes every baseline if touched.

## Lessons from the previous Design System

Copied from BUILD-PLAN Appendix B on 2026-09-25. Each was learned in Design System 1.0 by measurement or by a real defect; the step that applies it cites it.

- **2026-09-25 — B.1 Language tags name the script.** Always `sr-Latn` / `sr-Cyrl`, never bare `sr`: `Intl` reads bare `sr` as Cyrillic, which once produced Cyrillic month names on a Latin screen for weeks. Treat `sr-RS` as Latin (everyday Serbian usage).

- **2026-09-25 — B.2 Two locales that barely differ hide bugs.** Bosnian and Serbian share about two thirds of their strings; a stale setting rendered Bosnian for an afternoon while everyone believed it was Serbian. Any language picker shows the current language.

- **2026-09-25 — B.3 Number entry.** A masking input configured for Serbian turned `1234.56` into `123456` — a hundredfold error on the form people type when copying from foreign invoices. Hence no mask: parse the raw text. Accept `1234.56`, `1234,56`, `1.234,56`, `1,234.56`, grouping by space, non-breaking space, thin space or either apostrophe, and Indian 2-2-3 grouping. **The rule:** with both separators present, the last one is the decimal separator; with one kind present, it is a decimal separator when it appears once and grouping when it repeats; the screen's own number scheme is consulted **only** to break a tie the string cannot break itself (a string that is exactly a grouped integer in the scheme's own grouping, e.g. `240.000` on a dot-comma screen, is read as grouped). The alternative "under dot-comma a dot is never a decimal" breaks `1234.56` and was rejected. What the system prints, it must be able to read back — test every scheme's output through the parser.

- **2026-09-25 — B.4 Unreadable is `null`, never `0`.** An unparseable amount counted as zero once made an unbalanced journal entry look balanced. Also: `value * 100` is not a conversion (`1.005 * 100` is `100.49999999999999`); work on the decimal string. This was fixed once and reintroduced by a "simplification".

- **2026-09-25 — B.5 Tables.** Rendering both the desktop table and the phone cards and hiding one with CSS gave 1,592 ms per interaction at 932 rows; real branching plus virtualisation gave 120 ms. `table-layout: fixed` made columns worse. An empty value is an em dash (—), never a hyphen, which reads as a minus sign. Amount and currency joined by a non-breaking space so they never wrap apart. Raw numbers, not formatted text, go into CSV and Excel.

- **2026-09-25 — B.6 Contrast.** Opacity on text enters the contrast ratio (`opacity: 0.85` dropped a bar from passing to 4.31:1) — make quieter text with size and weight. Translucent dark-theme tokens assume the page background; on a coloured surface they mix (a tone on a blue bubble measured 2.34 instead of 6.32) — layer them over an opaque base. Status `solid` colours are for bars and dots, never text; text on a tone is its `fg` on its `bg`. Automatic contrast switching was measured and rejected: the threshold between two families was three thousandths apart. Contrast is measured after layers composite, not per token.

- **2026-09-25 — B.7 Right-to-left.** Three drag handlers (column resize, split divider, their arrow keys) all ran backwards in right-to-left because they computed in physical pixels. Every pointer or keyboard movement measures from the **leading** edge. This is a class of bug, not an incident. Progress bars flip (a bar is a metaphor for reading); prop names like `left`/`right` and symmetric stretches do not.

- **2026-09-25 — B.8 Ways of working that the owner established.**
  - Navigation is a **launchpad of module cards** at the root and **tabs inside a module**, not a sidebar.
  - **Full page** for creating or editing anything with more than about ten fields, tabs or attachments (it has an address, room for errors, and a back button); **drawer** for a short edit with the list still visible; **modal** for one action with one outcome, or a read-only view.
  - Routes: `/things`, `/things/new`, `/things/[id]`, `/things/[id]/part`; breadcrumbs from the third level; the table never decides whether a row opens a page or a drawer.
  - Actions at the top **and** at the bottom of a scrolling form; the bottom bar is sticky only while the form actually scrolls.
  - On a list: search on the start side, filters beside it, actions at the end, paging at the bottom. Once a user knows where search is on one screen, they know it on every screen.
  - One filled button per screen; the main action is last in its group.
  - The error sits next to the field. Success messages disappear; errors wait.
  - Hidden fields are never submitted.
  - A table on a phone is not a table: it is cards.
  - Confirmation does not scale: a bulk action asks once, with the count.

- **2026-09-25 — B.9 Habits.** A prop that is accepted and does nothing was found eleven times, and none failed lint, types, tests or the accessibility sweep — each was found by looking at a screen. Initials come from first and last name ("Ana Jovanović" → AJ, not AN). A finding is a hypothesis until code confirms it. When a check fails on more places than a change could touch, suspect the environment (a crashed dev server once failed 166 of 198 accessibility tests).

- **2026-09-25 — B.10 Packaging.** A package whose `files` field missed a sibling folder worked inside the workspace and returned errors for every consumer; a package marked private could not be installed at all. Workspace links hide both. That is why `consumer-check` installs **packed** tarballs. Every build tool task declares its outputs (a missing declaration once filled a cache to 223 GB).

- **2026-09-25 — B.11 The JMBG sex marker is not gender identity.** Never prefill anything about a person's gender from an identification number. (Domain validation itself is not in the Design System; this is recorded for whoever builds forms on it.)
